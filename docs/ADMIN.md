# 内容后台（/admin）

后台用来**在浏览器里直接编辑网页显示内容**：改完点保存，前台刷新就能看到，
不需要登服务器改 `site.js`，也不需要重新构建、重启服务。支持把内容导出成
JSON 留档 / 迁移，以及从 JSON 导入恢复。

## 数据是怎么流动的

```
构建时：src/data/site.js ──vite build──> dist（默认内容，打包进 JS）
运行时：content/site.json ──GET /api/content──> 前台与默认值深合并
         ↑ PUT /api/content（要 token）
         └──── /admin 后台「保存」
```

- `src/data/site.js` 仍是**兜底默认值**：首屏第一帧直接渲染它（不闪空白），
  部署在 GitHub Pages 等没有 API 的地方也照常工作。
- 后台保存写的是 `content/site.json`（全量快照）。前台打开页面时拉这份
  内容与默认值深合并 —— 缺的字段自动回退默认值，所以内容文件旧一点也不会崩。
- `index.html` 的 `<title>` / og 分享卡片由服务器在响应时替换成线上内容里的
  `meta`，微信 / QQ 爬虫（不执行 JS）也能拿到新值。

## 口令：默认口令 + 首次登录强制修改

口令按优先级取三个来源（`server/auth.cjs`）：

| 优先级 | 来源                               | 何时生效                                         |
| ------ | ---------------------------------- | ------------------------------------------------ |
| 1      | `content/admin-auth.json`          | 在后台改过口令之后（scrypt 加盐哈希，权限 0600） |
| 2      | `ADMIN_PASSWORD` 环境变量          | 部署时注入、且还没在后台改过口令                 |
| 3      | 仓库内置默认口令 **`xiaji-admin`** | 以上都没有（开箱即用）                           |

- **用默认口令登录会被强制改密**：登录后先弹出「设置新口令」，改完才能进入
  编辑器；服务端同样会拦 —— 没改之前 `PUT /api/content` 直接返回 403。
- 新口令至少 10 位，不能等于默认口令、也不能和当前口令相同。
- 改完口令后旧口令立即失效，**所有已登录设备的 token 也立即作废**（token 的
  签名密钥由当前口令派生）。
- 想用环境变量当初始口令（跳过强制改密），部署时带上 `ADMIN_PASSWORD=...`
  即可；一旦在后台改过口令，环境变量就不再参与校验（以文件为准）。

### 首次启用（生产服务器）

```bash
cd /var/www/xiaji-home
npm ci && npm run build
pm2 delete xiaji-home                     # 旧进程如果起错了脚本，先删掉
pm2 start ecosystem.config.cjs            # 不配环境变量就用默认口令
```

然后打开 `https://你的域名/admin`，用 `xiaji-admin` 登录，按提示设置自己的口令
（一次登录管 12 小时，「保持登录」管 30 天）。

> 想指定初始口令而不是用默认的：`ADMIN_PASSWORD='你的长口令' pm2 start ecosystem.config.cjs`。
> 之后想换口令，直接在后台「改口令」里改，不必再碰服务器。

## 怎么进后台

两种方式，效果一样：

- 直接打开 `https://你的域名/admin`；
- 页脚左下角 **GH / DC 那一排小方块里的 `AD`**（只在自托管、`/api` 真的在跑时
  出现；纯静态平台不显示，免得点进去登不上）。`site.js` 里手写了 AD 也兼容，
  不会重复渲染。

## 字体：两条路径，全站换字体

字体的来源有两条，后台「字体」分区里都能直接选：

### 1. 项目 `font/` 目录（随仓库走，推荐）

```
font/
├── PingFang.ttf                 # 单文件直接放
├── SmileySans/                  # 一个字体一个文件夹（下载的字体包常带
│   ├── SmileySans-Oblique.ttf   #   LICENSE，就整个文件夹放进来）
│   └── LICENSE.txt              #   —— 非字体文件自动忽略
```

- **自动遍历**（含子文件夹），支持 `.ttf / .otf / .woff / .woff2`（大小写都认）；
- 构建时由 Vite 打包进 `dist/assets/`，**GitHub Pages 这类没有后端的静态
  部署同样可用**；
- 增删字体后要重新 `npm run build` 才进产物；dev 下如果后台没刷新出来，
  刷新一下页面即可（glob 在模块加载时展开）。

### 2. 后台上传（存在服务器上，免构建）

- 支持 `.ttf / .otf / .woff / .woff2`，单个最大 **25MB**，字体库最多 **20** 个；
- 上传 / 删除需要登录（和保存内容同一道口令闸）。

### 使用与回退

- 三个角色：「正文字体」管整站默认，「标题字体」只作用于 `h1~h4`（留空跟随
  正文），「等宽字体」管 `.mono` 小字标签。选择后点右上角**保存**才生效。
- 删除字体后，正在使用它的角色自动回退默认字体栈（Inter / 系统栈），不会白屏。
- 自定义字体只排在字体栈**最前面**：字体缺字形（比如英文-only 字体遇到中文）
  时回退到默认栈，排版不会崩。
- 上传的字体由服务器以同源静态地址（`/api/fonts/file/<名>`）提供，带 immutable
  缓存；CSP 的 `font-src 'self'` 天然放行。
- 部署在纯静态平台时上传不可用（没有 `/api`），但 `font/` 目录的内置字体照常
  可用，全站至少有一种换字体方式。
- 内容 JSON（导入 / 导出）只记录字体的 **id 引用**，不含字体文件本身；迁移到
  新机器时请把 `font/` 目录和 `content/fonts/` 一起拷走。

## 导入 / 导出

- **导出**：把当前编辑器里的内容下载成 `site-content-日期.json`。
  建议每次大改前导出一份留档。
- **导入**：选择之前导出的 JSON（或手工编辑的），载入**编辑器**——
  此时并没有生效，检查一遍后点**保存**才会写到服务器。
  兼容两种形状：完整的 `{ site, sectionTabs, navLinks }` 或裸的 site 对象。
- 服务器上还有自动备份：每次保存前，旧内容会拷一份到
  `content/backups/site-时间戳.json`，保留最近 10 份。改坏了又没导出过，
  登服务器把最近的备份拷回 `content/site.json` 即可。

## 安全说明

- 写接口（`PUT /api/content`、上传 / 删除字体）必须带登录 token；
  **还在用默认口令时写入一律 403**。
- 口令不在代码里明文流转：落盘的是 scrypt 加盐哈希（`content/admin-auth.json`，
  权限 0600）；token 的签名密钥由当前口令的哈希派生，服务重启不失效、改口令
  立即全体作废。
- 登录 / 改密错误 5 次锁同一 IP 10 分钟。
- 内容写入前做结构校验（只允许字符串 / 数字 / 布尔 / 对象 / 数组，≤512KB，
  嵌套 ≤8 层），并且**原子写**（先写临时文件再 rename）——断电也不会留下
  半个 JSON。
- 前台渲染没有任何 `dangerouslySetInnerHTML`，内容全部按纯文本转义。

## 常见问题

**保存了，前台怎么没变？** 前台是打开页面时拉内容，刷新一下就好；
`index.html` 本身是 `no-cache`，不会吃到旧缓存。

**后台改了 `meta`，微信分享卡片还是旧的？** QQ / 微信的爬虫缓存很顽固，
等它自己过期，或在对应的分享调试工具里刷新。

**想回到构建时的默认内容？** 后台删掉服务器上的 `content/site.json`
（或把它改名），前台就会回退到打包进去的 `site.js`。

**口令忘了 / 想重置？** 口令哈希在服务器的 `content/admin-auth.json` 里：

```bash
rm content/admin-auth.json     # 回到默认口令 xiaji-admin（或环境变量口令）
pm2 restart xiaji-home --update-env   # 不需要，但重启一下最稳妥
```

删掉后用默认口令登录，会再次要求设置新口令。注意环境变量 `ADMIN_PASSWORD`
只有在这个文件不存在时才生效。
